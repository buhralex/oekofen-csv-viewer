**BUGS TO FIX (found during 29-check human verification):**

**Bug 1 — Check 6 / "All" default shows only 3 columns:**
User reported: "default has only 3 columns." The "All" tab (default on file load) shows only 3 series instead of the expected 9 from DEFAULT_SERIES.

Most likely cause: `applyRestoredPrefs()` is restoring old localStorage prefs that have only 3 series (from a previous manual test), overriding the "All" default. The restore runs after chart creation and applies whatever was saved before. This would be correct behavior IF the user had previously saved a 3-column state — but it creates a confusing "first impression" when the user expects DEFAULT_SERIES.

Alternative cause: `buildViewPresets()` is filtering DEFAULT_SERIES against `dataModel.columns` and only 3 of the 9 DEFAULT_SERIES rawNames match. Investigate by checking if the file's column names exactly match DEFAULT_SERIES entries (e.g., encoding of `°` in `AT [°C]`).

**Debugging steps:**
1. Open DevTools → Application → Local Storage — check what's in `oekofen-viewer-prefs`. If it has `visibleSeries` with 3 entries, this is the restore bug.
2. Clear localStorage, reload, drop CSV — does "All" show 9 columns? If yes, restore is the culprit. If still 3, it's a buildViewPresets() filtering issue.
3. Check console for `[buildChartData] rawName not found` warnings — these indicate DEFAULT_SERIES rawNames that don't exist in the file.

**Bug 2 — Checks 7-10: Legend clicks do nothing:**
User reported: "Nothing happens. I can click them, but they don't get displayed." Clicking legend rows does not toggle series visibility.

Most likely cause: `setSeries()` IS being called but the visual update isn't reflecting on the chart. Could be:
- `pointer-events: auto !important` was applied in CSS but something else is overriding it at runtime
- The click handler fires but `u.series[seriesIdx].show` is already `false` (toggling hidden → hidden) because Bug 1 left some series hidden
- OR: `applyLegendRowStyle()` is applying opacity:0.35, but the series line on the chart is NOT actually hiding — meaning `setSeries` call is not reaching uPlot (e.g., AppState.chart is null at click time)

**Debugging steps:**
1. Add `console.log('legend click', seriesIdx, currentShow, newShow)` to `wireLegendClicks` handler and retry
2. Check if `AppState.chart` is non-null at click time
3. Verify `.u-legend` has `pointer-events: auto` in DevTools → Computed styles (not just Elements tab)
4. After clicking, check `AppState.chart.series[i].show` in console — did the state actually change?
